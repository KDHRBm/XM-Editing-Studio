# 原生水印画面错位修复

验证日期：2026-11-17，Windows x64。

## 原因

真实 H.264 输入为 1080×1922、60 fps。Source Reader 初始返回 RGB32、stride=4320；读取首帧时发出 `MF_SOURCE_READERF_CURRENTMEDIATYPECHANGED`，实际缓冲区变为 1088×1936、stride=4352，显示区域仍是 1080×1922。旧逻辑忽略通知，并将扩大后的缓冲区按原宽度交给编码器，导致逐行错位。水印在错误布局上合成，因此文字正常而底图严重拉丝。

## 处理

- 读取初始及变化后的 RGB32 布局，区分存储尺寸、行跨度、可见区域和输出尺寸。
- 优先通过 `IMF2DBuffer.Lock2D` 获取真实行跨度；普通缓冲区校验有效长度，兼容正负 stride。
- 裁取显示区域，复制为明确的紧密排列正向 RGB32 帧后再叠加水印；编码器始终接收固定尺寸的规范帧。
- 保留原 sample 的时间戳、时长与属性；异常布局停止任务，不生成已完成的花屏输出。
- Source Reader 不支持缩放时，在帧规范化阶段完成所选分辨率缩放。
- 运行时继续使用 Windows Media Foundation；未增加 FFmpeg 等运行依赖。

## 验证

`node --test tests/test-native-watermark.mjs tests/test-watermark-processing.mjs tests/test-browser-watermark.mjs`

17 项通过，0 失败、0 跳过。新增测试覆盖带填充的正负行跨度、非零裁剪偏移、sample 时间信息、截断缓冲区拒绝，以及 1080×1922 竖屏、854×480 横屏、480p 缩放的非均匀图案画面比对、音轨与时长。

实际整集验证：约 223.72 秒，13421 帧全部保留，输出 1080×1922、60 fps，AAC 音轨保留，整段解码无错误。8、45、90、150、215 秒的非水印区域 RGB 平均绝对差为 1.09–1.61/255；旧故障输出为 24.99–70.98/255。原视频与既有输出均未覆盖。

本地安装仅替换水印引擎、引擎哈希描述和程序清单；已备份原文件，153 个程序文件校验通过。此修复尚未发布到 GitHub。
