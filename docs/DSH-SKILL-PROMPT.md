# 公司 DSH 音乐分析：默认调用 xm-script-music

更新日期：2026-11-18。

## 目标与接口

修改类型为现有提示词优化。目标是公司 DSH 网页中的音乐分析；服务端实际模型名称、版本及 Skill 加载工具未知，采用通用文字调用约定，不假设特定工具名。默认请求已安装的 `xm-script-music`（剧情分析与配乐策划），无须用户每次手动输入技能名。

软件掌握本轮阶段、候选白名单、动态结果结构和任务标识；服务端掌握 Skill 安装与加载。不能仅凭生成的提示词确认远端已加载 Skill。

本次保持单集、多集、整集、分段、补充和纠错的既有接口，不添加模型请求轮次。成功标准：每个 DSH 音乐请求均携带技能调用和阶段约束；原文与候选传递保持完整；推荐理由用中文；输出继续通过现有解析与避重校验；其他提供商及 Suno 任务不使用该调用规则。

## 提示词改动

完整生效文本由 `dshKeywordMessages`、`dshMatchMessages` 和原有 `webTaskPrompt` 共同生成。

- 每轮开头明确默认调用已安装的 `xm-script-music`，包括补充与纠错。若服务端无法加载，按内置规则继续，不伪称已调用，不自动安装或下载。
- 第一阶段只返回剧情分析、分段及检索词；第二阶段仅从当前候选中选曲并给出逐曲中文理由，不能重新开始剧情分析。
- 当前软件结构优先于 Skill 中的示例；保留 `xmTaskId/result`、`id/ref` 和现有层级。单集不因可选集号缺失而停止。
- 情绪判定基于原文证据：关心不默认是阴谋，电话确认的事实可采信，目标完成时允许释然与胜利；不编造结局。
- 以剧情情绪和配乐用途优先，允许用户指定的反差配乐；不把 Trap 或含糊曲名机械理解成具体剧情，不虚构未试听音频的特性。
- 保留 30–80 字中文理由、候选白名单及三集避重，历史检查限于提供的记录、软件过滤与同批结果。

## 方案比较

以下为静态设计评审，不是模型效果评分。

| 方案 | 评审结论 |
|---|---|
| 只在首轮增加技能名 | 匹配、重试和补充缺乏独立调用提示，旧有偏差规则仍在；不采用 |
| 每轮复制完整 Skill | 重复传递长规则，增加输入长度且形成多个维护来源；不采用 |
| 每轮简短调用 + 阶段与协议 + 保留关键内置规则 | 使用此方案；保证当前流程兼容，远端不可用时仍有既有分析能力 |
